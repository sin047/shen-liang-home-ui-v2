# 教程研究笔记

用户提供的教程是经验参考，不是本项目的技术规范。采纳前需要结合当前需求、版本和授权重新验证。

## 1. 人机前端开发踩坑手册_公开分区版.docx

主要价值：
- 将聊天、上下文、媒体、WebView、语音、外部平台、记忆、动态流和高级材质等问题分区；
- 强调构建成功、部署成功、功能成功和真实设备成功是不同层次；
- 有副作用的请求超时后不能盲目重试；
- 修复前先确认真正运行的源码位置，避免旧工作区与现役版本漂移；
- 主题与材质不能顺手覆盖布局属性；
- WebView 与原生 Compose 不属于同一渲染树，不能假设材质可以直接穿透；
- 复杂玻璃和 WebGL 效果必须在目标设备验证性能、滚动和回退。

采纳范围：作为未来工程风险与回归测试参考。大量具体案例与当前项目功能无关，应按功能存在与否选择阅读，不照搬整套实现。

## 2. 自建小家tips.docx

主要价值：
- 区分 UI（长什么样）、前端（怎么交互）和后端（数据与服务）；
- 提需求时说明触发方式、视觉反馈和完成结果；
- 一次改一处，先做常用能力；
- 密钥不放在前端；
- 修改后检查真实界面，而不是只听 AI 汇报；
- 第三方素材应注意是否只允许个人使用。

采纳范围：作为产品表达和素材安全的通俗参考，不据此决定本项目使用原生 App、PWA 或特定后端。

## 3. 小前台大后台.pdf

主要价值：
- 将面向用户的对话层与实际执行任务的后台分离；
- 使用任务台账、异步委派和明确的终态来避免任务结果丢失；
- 对超时、取消、进程退出等情况明确标记“结果未知”，不自动重放。

适用性：该文档针对特定版本 Claude Code、bridge 和后台进程架构，技术细节高度具体。当前项目尚未确定后端与 Agent 架构，不采纳其代码或参数；仅保留“任务状态必须可追踪、未知不能冒充成功”的原则。

## 4. 前端搭建完整教程.docx

主要价值：
- 持久数据应有明确的权威存储；
- 前端聊天、多模态媒体、后端 API 和长期记忆需要清晰边界；
- 设计密钥与网关凭据必须放在受保护的服务端环境；
- 主题、人设、动态记忆和聊天历史不应无差别重复注入。

适用性：教程给出了特定 Flask / SQLite / Anthropic API 方案，但这些不是本项目的技术选型。当前仓库只负责 v2 前端规划，不复制其中的服务端代码或密钥配置。

## 5. 人机恋之零基础搭建属于自己的前后端小家：开工工作流手册.docx

主要价值：
- 先用产品经理式提问把需求问清楚，再写产品描述；
- 技术栈是重要且难回头的决定，应先比较并独立复核；
- 建立项目指令、产品文档、现状快照、构建规则、已知问题和远景规划；
- 方案、复核、施工、测试和用户验收应分工；
- AI 的汇报不能代替文件、测试、commit 和真实页面证据；
- 前端设计稿需要翻译成版本化 Design System；
- 前后端接口要形成共同合同，一次接入一个功能；
- PR、备份、回滚和不可逆操作应由用户把关。

采纳范围：作为本项目的协作流程和验收原则。技术栈与部署部分仍待单独讨论。

## 6. 本项目的采纳结论

当前明确采用：
- 先讨论、再确认、再施工；
- 设计稿与 Design System 分离；
- 以用户确认的决策记录为权威；
- 小步修改、最小差异、分模块验收；
- 真实设备和真实交互必须有证据；
- 公开仓库不提交秘密和未授权素材。

当前不采用：
- 未经讨论就照搬某个教程的完整后端；
- 未经验证就使用特定 API、数据库、模型网关或 Agent 架构；
- 把示例中的配置数字、性能数据或版本结论当成本项目事实。
