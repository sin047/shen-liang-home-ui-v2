# 主题系统

**状态：核心方向 CONFIRMED；机制细节待设计**

## 1. 默认主题

默认主题为「雾蓝珍藏室」，日间和夜间是同一主题体系中的两种模式，而不是两个互不相关的皮肤。

## 2. 扩展能力

用户确认的目标是：
- 默认主题本身完整、精心设计；
- 后续可以增加其他主题；
- 支持区域级混搭，不要求整个界面永远只能使用一套外观。

具体的主题包格式、区域覆盖方式和设置入口尚未确定。

## 3. 设计分层建议

建议未来将主题拆成：
- **基础色板**：来自原始日夜色卡；
- **语义 Token**：正文、次级文字、背景、边界、强调、成功、警告、错误等；
- **组件 Token**：按钮、卡片、输入框、导航、弹层等；
- **材质 Token**：模糊、透明度、高光、折射、阴影；
- **区域主题**：允许特定空间覆盖自己的视觉变量。

以上是设计建议，需在 Design System 阶段验证后冻结。

## 4. 主题覆盖原则

- 主题负责外观，不应顺手接管布局、尺寸、滚动、定位和业务状态。
- 默认主题应使用正常的层叠优先级，不能通过全局高优先级规则压死自定义主题。
- 区域混搭要明确覆盖范围、优先级、回退值和切换时机。
- 同一组件在日夜主题下应保持相同的交互语义。
- 不能只检查颜色变量是否存在，还要检查实际页面的对比度和可读性。

## 5. 待确认

- 用户是否能逐区域选择主题；
- 是否提供预设组合与自定义组合；
- 日夜模式是否跟随系统或手动切换；
- 区域主题和全局日夜模式冲突时谁优先；
- 主题切换是否需要过渡动画；
- 用户自定义主题是否允许上传素材。
