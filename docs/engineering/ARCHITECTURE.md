# 架构规划

**状态：未选型；仅记录边界与原则**

## 1. 当前仓库事实

当前仓库只有 README.md 和 .gitignore，没有应用源码、package manifest、构建脚本或 API 合同。

因此：
- 不能推断当前已经使用 React、Vue、Vite、Next.js 或其他框架；
- 不能推断 Glass Material Kit 0.5 已经安装；
- 不能推断已经有后端、数据库、模型 API 或部署服务；
- 不应通过初始化脚手架来“补齐”这些空白。

## 2. 仓库职责

本仓库是 v2 前端项目的规划与后续前端工作区。旧版家园和 UI playground 保持独立。

未来是否需要拆分后端仓库、共享组件库或素材仓库，等技术方案阶段再讨论。

## 3. 需要讨论的架构问题

- 目标运行环境：移动网页、PWA、桌面网页或原生 App；
- 前端框架、构建工具、样式系统与状态管理；
- 路由和多空间信息架构；
- 主题 Token、区域混搭和素材加载方式；
- 聊天服务、模型 API、记忆和文件由哪个后端负责；
- 身份验证、权限、数据持久化和错误处理；
- API 合同、流式消息和多模态附件；
- 部署、回滚、监控和备份责任。

## 4. 规划原则

- 先明确每种数据的权威来源，避免前后端各存一份真相。
- 前端负责呈现与交互；持久数据由明确的服务端权威管理。
- API Key 和服务端凭据不进入浏览器代码。
- 每次只接入一个功能，并先写明接口输入、输出、错误和状态。
- 技术选型优先考虑主流程度、模型熟悉度、可维护性、移动端能力和验证成本。
- 不为未来可能出现的功能提前搭建复杂系统。

## 5. 技术选型流程

1. 用户确认目标平台与核心交互；
2. 提出少量可比较的候选方案；
3. 说明优缺点、成本、风险和模型施工可靠性；
4. 由独立视角复核；
5. 用户确认后写入决策记录；
6. 才能初始化工程。

在此之前，技术栈状态保持“未决定”。
