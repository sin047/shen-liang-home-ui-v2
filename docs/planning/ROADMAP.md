# 路线图

**当前阶段：Phase 0 — Design & Planning**

以下后续阶段是规划建议，不构成自动开工授权。

## Phase 0 — 讨论与规划

**状态：ACTIVE**

- 建立项目文档体系；
- 明确产品空间与信息架构；
- 确认视觉基线、导航、日夜主题；
- 研究材质、素材和组件；
- 整理架构选项与工程风险；
- 维护待确认问题与决策记录。

### Phase 0 退出条件

- 产品说明和功能矩阵经用户确认；
- 全局导航与主要空间关系经用户确认；
- 日夜主题色彩和区域混搭规则有可执行规格；
- 材质与动效边界明确；
- 关键视觉素材的来源与授权清楚；
- 技术栈和架构方案经过讨论与复核；
- 质量验收标准明确；
- 用户明确批准进入施工阶段。

## Phase 1 — 视觉设计与 Design System

**状态：PROPOSED**

输出应包括页面结构、关键状态、组件规范、主题 Token、字体与排版、响应式规则、交互说明和视觉验收样例。设计稿需要翻译为可复用的 Design System，不能让施工代理每次凭图自行发明样式。

## Phase 2 — 技术方案与工程基线

**状态：PROPOSED**

在视觉目标明确后，核实平台范围、技术栈、目录结构、依赖策略、后端接入边界、API 合同、测试方式和部署方案。选型需考虑模型对该技术栈的熟悉度、维护成本、移动端表现和长期可扩展性。

## Phase 3 — 前端静态骨架

**状态：PROPOSED**

先完成主要空间、导航和页面结构。未接入真实后端的区域可以明确标注为占位状态，不使用假数据冒充真实功能。

## Phase 4 — 分模块接入功能

**状态：PROPOSED**

一次接入一个模块；每个模块先定义前后端合同，再实现、测试和验收。避免一次性连接所有功能导致问题难以定位。

## Phase 5 — 视觉与真实设备验收

**状态：PROPOSED**

对照 Design System 检查桌面与移动端、日夜主题、键盘、安全区、滚动、材质回退、无障碍与性能。构建成功不等于真实设备验收成功。

## 重要顺序说明

教程建议在设计稿前考虑技术栈，以避免设计目标与工程能力脱节。本项目目前仍处于 Phase 0；技术栈会作为进入实施前的必经议题讨论，但不会在用户未确认时提前锁定或初始化。
