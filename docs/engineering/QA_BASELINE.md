# 质量验收基线

**状态：验收原则已整理；具体测试工具待技术栈确定**

## 1. 证据原则

构建成功 ≠ 部署成功 ≠ 功能成功 ≠ 真实设备成功。

每次交付都应明确：
- 修改了哪些文件；
- 运行了哪些检查；
- 通过 / 失败数量；
- commit 或 PR；
- 真实页面截图或交互证据；
- 哪些内容仍未验证。

没有证据时，结论应标记为未知或未验收。

## 2. 设计阶段验收

- 关键页面有明确的信息层级；
- 导航入口、展开、返回和选中状态有定义；
- 日间与夜间主题均有对照样例；
- 默认主题与区域混搭规则没有冲突；
- 字体、字号、间距和对比度可读；
- 装饰不遮挡内容与触控区域；
- 生成图中的错误文字和未经确认元素已剔除。

## 3. 前端阶段验收

技术栈确定后，再建立对应自动化测试。至少考虑：
- 桌面与窄屏布局；
- iOS Safari / Android WebView（如纳入目标范围）；
- 安全区、键盘弹起、滚动与弹层层级；
- 页面无意外横向溢出；
- 日夜主题和区域混搭；
- 主题切换时布局与业务状态保持稳定；
- 交互热区、加载、空状态、错误状态；
- 减少动态效果和低性能回退。

## 4. 材质验收

- 真实背景穿透与模糊效果；
- 滚动时位置和遮罩稳定；
- 目标设备帧率与 GPU 负载；
- 静止时是否停止不必要的动画；
- 不支持效果时的降级外观；
- 文字对比度与焦点可见性。

## 5. 变更验收

- 施工前读取相关设计与架构文档；
- 改动范围与任务目标一致；
- 不覆盖无关文件；
- 独立复核设计与真实代码的语境差异；
- 先跑自动化检查，再看真实页面；
- 通过 PR 供用户检查；未经授权不合并、不部署。
